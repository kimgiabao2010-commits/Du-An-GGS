# Durable bounded dispatch - Codex

Migration019 adds a Control Plane-owned singleton row. Ctrl+Shift+B requires `GSS_BOUNDED_DISPATCH=true`; lab/replay and a real staging authority activate it during readiness. Existing manually started legacy local staging-profile instances can retain disabled compatibility state until explicitly activated. Once persisted enabled, changing environment cannot disable it. Activation refuses multiple/unknown running investigations. No lifecycle/queue writer is moved to UI/workers.

The bound is32 logical work items, not32 copies of the same task. Queued/dispatched/running/blocked-without-result tasks and unpublished dispatch intents use idempotency keys to deduplicate. Initial/next-step task creation and Frontier/outbox commits take the same PostgreSQL transaction row lock. Full capacity returns503 `dispatch_queue_capacity_exhausted` without a partial new case/task/outbox/Frontier. Matching task replay still succeeds and changed-body reuse still409. A result transaction that cannot commit is retried; no fake evidence/success.

Initial and decision pg-boss queues share one durable run slot. FIFO selects a run across both kinds; follow-up evidence stays in that run while it has running tasks or unpublished intents. Restart, delivery lease expiry, offline backoff or worker failure never by themselves authorize another run. Terminal task plus no outstanding intent releases the slot on the next acquisition. A head run can block others until its intent is explicitly retired/reconciled; safety takes precedence over silently dropping it. Invalid intent/provenance remains fail-closed and requires operator attention.

This bounds **worker investigation dispatch**, not all incoming conversation commands, model calls or historical records. Global command admission/model inference concurrency needs a separate gate; per-call limits still apply. Queue delivery is not exactly-once worker execution; existing acceptance/result/idempotency protocols remain authoritative. Single host/slot is not HA.

Recheck persisted run state/deadline when creating or dispatching a task, not only when planning. Validated terminal/expired initial or decision intents are retired atomically with audit; queued/blocked tasks can be CANCELLED without an execution/result/evidence. Running workers are never silently cancelled by retirement and still fence the slot until their terminal state/result/watchdog is known. Invalid hash/provenance remains quarantined rather than retired as success. Oversized legacy backlog (>32) also refuses activation; no history is removed.

Upgrade safely: stop old launchers; inspect local target/schema/ledger/checksum; back up local PostgreSQL before `db:migrate`; never migrate a remote/staging DB from this rehearsal. Then use Ctrl+Shift+B. Activation with mixed execution state fails startup rather than canceling tasks. Do not edit the singleton or task status manually merely to show PASS. Monitor503 admission, head-intent last_error/retry and worker unknown-execution states. Halt remains durable and blocks new claims.
